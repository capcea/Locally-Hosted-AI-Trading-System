# Phase 5.5B — manual acceptance record

All manual items are NOT RUN / BLOCKED in this environment. This checklist is a reproducible review
plan, not WCAG certification or a usability study. Target: WCAG2.2AA, with stricter44px product targets.
Use disposable synthetic fixtures through real services, never owner recovery codes or broker secrets.

## Devices, inputs and layout

- Desktop Chromium and actual Safari, keyboard-only and VoiceOver; both themes.
- Actual mobile Safari/touch/keyboard in addition to Chromium iPhone13 emulation.
- Widths320,390,768,1024,1440 CSSpx; portrait/landscape,200% text and400% page zoom equivalents.
- Check all five navigation labels and active states, safe-area inset, long Romanian words, account IDs,
  hashes, URLs, form scrolling, table scroll and visible focus under any fixed navigation.
- No whole-page horizontal scrolling at320CSSpx. Necessary data tables may have labelled local scroll.
- Verify contrast on actual surfaces/hover/focus/error/disabled controls, not only palette calculations;
  high-contrast/forced-color and reduced-motion modes need direct observation.

## Keyboard and semantics

- Skip link reaches main; route changes focus the heading once; background polls never steal focus.
- All primary and advanced controls have matching visible/accessibility labels; select options do not
  contaminate names. Validation opens relevant advanced details before focusing the invalid field.
- STOP/CLEAR/FLATTEN each name account/scope, require acknowledgement and actual owner MFA. Dialogs
  keep keyboard focus inside, Escape works before submission and returns focus to the original control.
- Explain pending submitted operations and that closing navigation does not cancel server work.
- Screen readers announce actionable errors and real task changes without a percentage-update storm.
- Check all remaining specialized/legacy advanced controls, not just newly extracted primitives.

## Screen and journey review

- Home: explain availability/current work/results/attention/next action in ordinary language.
- Auth/setup: password manager, paste, manual TOTP, recovery saving, expiry and safe task return. Do not
  screenshot/trace authentication, provisioning URI, password, OTP or recovery-code states.
- Data: permitted source → instrument → actual timestamps/file → rights/calendar → review → real quality.
  Explain source-symbol errors, missing dates, degraded data and reference-only ECB observations.
- Research: prepared setup works; missing account/data/spec/context/profile/policy has a clear blocker
  and recoverable route; account change invalidates incompatible selections; holds remain protected.
- Progress: distinguish queued/running/retry, request acknowledged, actual cancellation and completion
  race; unknown submission has no blind new-key retry or automatic success.
- Results: identify net simulated change, largest historical decline, trade count, costs, coverage,
  in-sample/OOS distinction and uncertainty without opening JSON. Inspect exact tables, approximate
  chart sampling/gaps, trade/fill/replay decisions, fold boundaries, compare rejection and provenance.
- Accounts/safety: descriptive metadata is not enforced; policies are exact account/program/date versions;
  unknown/stale state never becomes available money or a successful emergency acknowledgement.
- Settings: locate every advanced simulator/connector/catalog/security/user/audit/diagnostic capability.
- Final evaluation: intentional separate owner flow; prior exposure remains unknown; one-use frozen
  authorization and resumption do not imply promotion or independence certification.
